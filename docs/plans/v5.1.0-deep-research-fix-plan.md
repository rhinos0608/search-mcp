# Deep Research Pipeline Fix Plan — V5.1.0 ✅

**Status**: Implemented in one batch. All 8 phases (source ingestion, source lifecycle tracking, prose synthesis, per-source summarization, browser fallback, freshness scoring, source diversity via circuit breakers, think_tool) are complete and merged.

Expanded from local investigation and analysis of `langchain-ai/open_deep_research` (LangGraph-based deep research agent).

## Summary of Patterns Borrowed from open_deep_research

| Pattern | open_deep_research | Our Current | Gap |
|---|---|---|---|
| Source summarization | Per-source LLM summary before synthesis | Raw content → compactContent 24k chars | Missing separate summarization step |
| Researcher compression | `compress_research` per worker with inline citations | `compactContent` + LLM synthesis from blocks | No per-worker structured compression |
| Reflection tool | `think_tool` used by supervisor + researcher between steps | EDA phase (Evaluate/Decide/Act) — rule-based gap detection | Less flexible than LLM self-reflection |
| Model routing | 4 separate models (research, summarization, compression, final_report) | 2 models (orchestrator, worker) | No compression/summarization model separation |
| Report prose prompt | Explicit: "by default, write in paragraph form" | Rule-based synthesizer builds `- bullet` lists | Fallback output is always bullet form |
| Citation system | Numbered [1], [2] with Sources section | `[Source N]` with linked Sources at end | Similar but ODR preserves source date/title in citations |
| Evaluation framework | 6 quality evaluators (groundedness extracts every claim) | None | No automated quality evaluation |
| Per-source type depth scoring | Not present in ODR either | Not present | Both pipelines can improve here |
| Source diversity enforcement | Relies on LLM search decisions | Relies on worker multi-backend search | Both pipelines can improve here |

## Borrowed Patterns → Our Pipeline Mapping

### 1. Per-Source Summarization (HIGH IMPACT)

**ODR pattern**: `tavily_search` → `summarize_webpage()` per unique URL → compressed findings → final report.

**Our adoption**: Instead of `compactContent` stuffing raw markdown into 24k chars, apply per-source summarization after `gatherContent`. Each `FetchedPage` gets LLM-summarized (or rule-based if no LLM) into a structured `SourceSummary { title, url, sourceType, domain, date, keyClaims: string[], excerpts: string[] }`. Then feed summaries, not raw content, into synthesis.

**Key benefit**: Fixes the 24k char budget issue (#6), preserves citations per-source, and makes source accounting trivial.

### 2. Per-Researcher Compression with Citations (HIGH IMPACT)

**ODR pattern**: `compress_research` node takes full researcher tool output and compresses it with "preserve ALL relevant statements verbatim... inline citations... Sources section."

**Our adoption**: After per-source summarization, run a compression step per worker that merges source summaries into a structured `WorkerSynthesis { narrativeSummary, findings, sourceMap }` with URL→citation-number mapping. This gives us:
- Full worker source tracking (fixes #2, #3)
- Citation continuity across synthesis
- Source-type preservation (fixes #1)

### 3. LLM Reflection / think_tool (MEDIUM IMPACT)

**ODR pattern**: `think_tool(reflection: string)` — takes a string, stores it. Supervisor calls it between ConductResearch spawns. Researcher calls it between searches.

**Our adoption**: Add `think_tool` to WorkerAgent's tool set. After each search round, worker reflects and decides whether to search more, refine queries, or stop. This adds agency without requiring architectural changes. Also add to orchestrator's EDA phase as a decision input alongside rule-based gap detection.

### 4. Separate Compression Model (MEDIUM IMPACT)

**ODR pattern**: `compression_model` (separate from `research_model`, `summarization_model`, `final_report_model`).

**Our adoption**: Add `DEEP_RESEARCH_COMPRESSION_MODEL` env var (defaults to worker model). The compression step uses a cheaper/faster model than the orchestrator. The summarization step can also use a separate model.

### 5. Report Prose Enforcement (HIGH IMPACT)

**ODR pattern**: `final_report_generation_prompt`: "use bullet points to list out information when appropriate, but by default, write in paragraph form."

**Our adoption**: Fix `buildNarrativeMarkdown` to produce flowing prose paragraphs grouped by theme, not bullet-point claim lists. When LLM synthesis is available, the prompt already asks for narrative — verify it's enforced. When rule-based fallback runs, generate coherent paragraph prose from claims + evidence, not `- claim [Source N]` bullets.

### 6. Source Appendix: Used + Discarded (MEDIUM IMPACT)

**ODR pattern**: Sources section at end of compressed research: "List of All Relevant Sources (with citations in the report)."

**Our adoption**: Add two source lists to final report:
- **Sources cited**: already exists as `## Sources`
- **Sources examined**: new section listing all WorkerReport.sources that were read but produced no findings, with discard reason

### 7. Freshness / Temporal Scoring (MEDIUM IMPACT)

**ODR pattern**: Not present — ODR relies on LLM search decisions and Tavily's recency bias.

**Our adoption**: Add `freshnessScore` to `SourceEntry` and `WorkerSource`. During `planSearch`, include freshness intent per sub-question. In `gatherContent`, compute temporal relevance: publishedDate within N years unless sub-question explicitly asks for historical. Penalize >5yr academic results for non-historical queries.

### 8. Browser Fallback Without extractionPlan (MEDIUM IMPACT)

**ODR pattern**: Not present — ODR uses Tavily which handles JS rendering server-side.

**Our adoption**: In `readPage`, add browser fallback when `content` is null or is a bot-challenge, regardless of `extractionPlan` presence. Use `InteractiveBrowserAgent` with default extraction (full page markdown) rather than requiring an extraction plan. Cap per-worker browser sessions and add timeout.

## Revised Phase Plan (ROI × Dependency Ordered)

### Phase 1: Fix Source Ingestion + Source Type Preservation

**Dependency**: None. **ROI**: Immediately fixes mislabeled sources and lost metadata.

**Changes**:
1. `ingestWorkerReports` (orchestrator.ts:567): Before ingesting findings, ingest all `report.sources` entries as `SourceEntry` in state. Build URL→sourceId map.
2. `ensureSourceExists` (orchestrator.ts:591): Remove `const sourceType: SourceType = 'web'`. Look up actual source type from `report.sources` by URL. Fallback to `'web'` only if URL not found in report.sources.
3. Link all `wf.sourceUrls` to source entries, not just `wf.sourceUrls[0]`. Use the URL→sourceId map.
4. Add helper: `getOrCreateSourceEntry(url, report)` that either returns existing sourceId or creates one with correct type.

**Files**:

- `src/research/types.ts` — no changes needed (SourceEntry already has sourceType field)

**Dependency**: Phase 1 (needs corrected source ingestion). **ROI**: Transparency, bug diagnosis.

3. In `workerAgent.ts`, track source lifecycle: searched → selected → read → (used | discarded). Record discard reasons.
4. In `ingestWorkerReports`, ingest all sources including discarded ones.
5. In `synthesizer.ts`, add `## Sources Examined` appendix listing discarded sources with reasons.

**Files**:

- `src/research/workerAgent.ts` — source lifecycle tracking
- `src/research/orchestrator.ts` — ingest discarded sources
- `src/research/synthesizer.ts` — examined sources appendix

### Phase 5: Browser Fallback Without extractionPlan

**Dependency**: None (can be done independently). **ROI**: Reduces silent failures on JS-heavy pages.

**Changes**:
1. In `readPage` (workerAgent.ts:520-580), after webRead/webCrawl fail or return <200 chars:
   - Check if browser tools are configured
   - If yes, attempt `InteractiveBrowserAgent` with default extraction (full page markdown, no action plan)
   - Add safety caps: max 3 browser pages per worker, 30s timeout per page
2. Remove the `extractionPlan` guard from bot-challenge detection — always try browser when bot challenge detected and tools available.

**Files**:
- `src/research/workerAgent.ts` — `readPage` method
- `src/research/interactiveAgent.ts` — may need a `extractPage(url)` convenience method

### Phase 6: Freshness / Temporal Relevance

**Dependency**: Phase 1 (needs source date metadata). **ROI**: Fixes stale arXiv papers appearing.

**Changes**:
1. Add `freshnessIntent` to SubQuestion type: `'recent' | 'historical' | 'any'`.
2. In `planSearch`, set freshness intent based on query classification:
   - `current-events`, `market-ecosystem` → `recent`
   - `historical-timeline` → `historical`
   - others → `any`
3. In `gatherContent`, after fetching each page:
   - Extract published date from content metadata
   - Compute freshness score: 1.0 for <1yr, linear decay to 0.1 at 5yr, 0.0 beyond
   - Penalize search results where freshness score < 0.3 AND freshnessIntent is `recent`
4. Store `freshnessScore` and `publishedDate` in `WorkerSource`.

**Files**:
- `src/research/types.ts` — SubQuestion.freshnessIntent, WorkerSource additions
- `src/research/workerAgent.ts` — planSearch, gatherContent
- `src/research/orchestrator.ts` — set freshnessIntent during decomposition

### Phase 7: Source Diversity Quotas + Per-Type Caps

**Dependency**: Phase 1. **ROI**: Prevents YouTube-dominated results.

**Changes**:
1. Add per-source-type caps: `maxPerSourceType: { youtube: 3, reddit: 5, academic: 10, web: 15, ... }`.
2. In `planSearch`, respect sub-question `preferredSources` but ensure minimum diversity: at least 2 source types represented.
3. In `gatherContent`, after dedup, apply source-type caps before reading.
4. Reduce YouTube default priority unless query is tutorial/video-appropriate.

**Files**:
- `src/research/workerAgent.ts` — planSearch, gatherContent
- `src/research/types.ts` — optional caps config
- `src/config.ts` — per-type cap env vars

### Phase 8: LLM Reflection / think_tool for Workers

**Dependency**: None (standalone enhancement). **ROI**: Better search quality, fewer wasted rounds.

**Changes**:
1. Add `think_tool` as a tool available to WorkerAgent (not surfaced to end user, internal only).
2. After each search round in the worker loop, call think_tool with reflection prompt.
3. Worker uses reflection to decide: search more, refine queries, or stop and synthesize.
4. Store reflection trail in WorkerReport for traceability.

**Files**:
- `src/research/workerAgent.ts` — tool set, main loop
- `src/research/llm/prompts.ts` — reflection prompt template

## Risk Notes

1. **SourceEntry extension**: Adding optional fields (`usageStatus`, `discardReason`, etc.) to `SourceEntry` is backward-compatible if optional. Existing code that creates SourceEntry without these fields will continue to work. But the constructor in `ensureSourceExists` must be updated.

2. **compactContent replacement**: The per-source summarization approach adds LLM calls (1 per source). With 10-30 sources per worker, this adds latency. Mitigation: do summarizations in parallel (already supported by the semaphore model), use a cheaper/faster model for summarization.

3. **Browser fallback cost**: Browser sessions are expensive. Cap at 3 pages per worker, 30s timeout each. If a site requires browser extraction for all 10 pages, the worker will get content from at most 3 browser pages + 7 regular fetches.

4. **Prose synthesis quality**: Rule-based prose generation is inherently lower quality than LLM-based. The fallback prose should be simple but coherent — "Sources indicate that X. This is supported by Y and Z. However, some sources disagree..." rather than bullet lists. When LLM is available, the prose quality should be high.

5. **Freshness scoring may drop legitimate sources**: A seminal 2017 paper may still be highly relevant for many topics. The freshness penalty should be configurable and disabled when `freshnessIntent` is `historical` or `any`.
