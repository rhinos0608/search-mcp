## 1. Audit Findings

### 1.1 Tree Engine Rabbit Holes (`treeEngine.ts`)

| Issue                     | Severity | Detail                                                                                                     |
| ------------------------- | -------- | ---------------------------------------------------------------------------------------------------------- |
| Single follow-up per node | HIGH     | Line 344–346: only `followUpQuestions[0]` is pursued. All other follow-ups are discarded.                  |
| No topic-drift guard      | HIGH     | Recursion follows LLM-generated follow-up questions with zero relevance check against the original query.  |
| Failed query noise        | MEDIUM   | Per-query failures produce `"No findings for: ..."` learnings that pollute aggregation output.             |
| Static word budget        | LOW      | `contextWordLimit: 25000` is global — doesn't account for branch fan-out compressing cross-branch signals. |

### 1.2 State Explosion (`state.ts`, `orchestrator.ts`)

| Issue                                                         | Severity | Detail                                                                                                                  |
| ------------------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------- |
| Unbounded state growth                                        | HIGH     | `ResearchState` accumulates sources, findings, gaps, contradictions indefinitely. No eviction, no tiering, no size cap. |
| Gap loop amplification                                        | HIGH     | Each gap loop spawns sub-questions → workers → more sources/findings. With 5 gap loops at `exhaustive`, state can 10×.  |
| No sub-question dedup                                         | MEDIUM   | Gap-filling generates new sub-questions textually — no Jaccard dedup against existing questions.                        |
| `maxExtractions` only bounds extraction count, not state size | MEDIUM   | 100 sources × 50 extractions = 5000+ findings possible — no cap on stored findings.                                     |

### 1.3 Pruning / Compaction Gaps (`compaction.ts`)

| Issue                       | Severity | Detail                                                                                                          |
| --------------------------- | -------- | --------------------------------------------------------------------------------------------------------------- |
| Post-hoc only               | CRITICAL | Compaction runs AFTER research completes. During research, state grows unbounded.                               |
| Transport-focused           | HIGH     | `compactResearchResult()` targets MCP response size — not orchestrator memory pressure.                         |
| No quality-ranked trimming  | MEDIUM   | Findings are dropped from the end of the array — not prioritized by confidence, evidence quality, or relevance. |
| No in-flight source pruning | HIGH     | Sources are never discarded once added, even if they produce zero findings.                                     |

### 1.4 Error Recovery (`discovery.ts`, `extraction.ts`, `workerAgent.ts`, `orchestrator.ts`)

| Issue                           | Severity | Detail                                                                                               |
| ------------------------------- | -------- | ---------------------------------------------------------------------------------------------------- |
| No retry for transient failures | HIGH     | Rate limits, timeouts, and network errors fail immediately with no backoff.                          |
| Single-pass recovery            | MEDIUM   | `recoverSubQuestion()` runs once and gives up. No escalating strategy (broader terms → LLM rewrite). |
| No circuit breaker              | MEDIUM   | A backend returning 100% errors (e.g., GitHub API down) is hammered on every discovery pass.         |
| LLM failures swallowed          | LOW      | Catch blocks log and move on — but finding count may silently drop, producing incomplete reports.    |

### 1.5 Timeout / Budget Tuning (`jobManager.ts`, `state.ts`)

| Issue                                           | Severity | Detail                                                                                                                      |
| ----------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------- |
| No confidence plateau detection                 | HIGH     | Gap loops continue until `maxGapLoops` exhausted — even when new findings per loop approaches zero.                         |
| Wall-clock timeout ignores progress             | MEDIUM   | `maxTimeMs` triggers abort regardless of whether results are improving.                                                     |
| Extension logic doesn't check yield             | MEDIUM   | `extendRuntime()` grants time but never asks "are we making progress?"                                                      |
| Budget exhaustion treats all dimensions equally | LOW      | `isExhausted()` doesn't prioritize — tool calls and time are equally weighted, but tool calls can be extended, time cannot. |

### 1.6 Citation Hallucination (new finding from research)

Recent research (arXiv 2604.03173v1) shows deep research agents hallucinate 3–13% of citation URLs,
with some models fabricating every broken URL. The `urlhealth` pattern (HTTP HEAD + Wayback Machine)
reduces non-resolving URLs by 6–79×. Our codebase has no citation URL validation whatsoever.

## 2. Competitive Landscape

| System                             | Key Technique                                                                                | What We Lack                                                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **gpt-researcher**                 | Tree exploration with `breadth/2` decay, `trim_context_to_word_limit()`                      | Context limit is per-node, not global — we could adopt this.                                                   |
| **STORM (Stanford)**               | Perspective-guided Q&A, outline-constrained output                                           | Outline-as-constraint prevents scope creep — we don't enforce outline adherence.                               |
| **OpenDev (OpenAI)**               | 5-stage Adaptive Context Compaction (ACC), doom-loop fingerprint detection, system reminders | We have none of these. Their staged compaction (70→80→90→99%) with observation masking is directly applicable. |
| **urlhealth** (arXiv 2604.03173v1) | HTTP HEAD + Wayback Machine for URL liveness, stale-vs-hallucinated classification           | We have no citation validation. Adding this prevents citing dead/hallucinated URLs.                            |

**Key takeaway:** The frontier is moving from "generate then compact" to "compact continuously."
OpenDev's ACC proves that staged, in-flight compaction is viable and effective (54% peak context
reduction). Their doom-loop detection (fingerprint tool calls, block after 3 repeats) is simple
and high-impact.

### urlhealth (arXiv 2604.03173v1) — 83-line Python classifier

```python
def classify_url(url):
    # HTTP HEAD (fallback GET on 405/403/501)
    resp = requests.head(url, timeout=5, headers={'User-Agent': browser_ua})
    if resp.status_code == 200:
        return 'LIVE'
    if resp.status_code == 404:
        # Check Wayback Machine
        wb = requests.get(f'https://archive.org/wayback/available?url={url}')
        if wb.json().get('archived_snapshots'):
            return 'DEAD'  # Stale — existed but now gone
        return 'LIKELY_HALLUCINATED'  # Never existed
    return 'UNKNOWN'  # 403, 429, 5xx, connection errors
```

URLs drop 6-79× to under 1%. Tool-use competence is critical: GPT-5-nano called the tool

## 3. Implementation Plan

### Phase A: In-Flight Pruning (Foundation)

_Estimated: 3–4 days. Touches: `state.ts`, `orchestrator.ts`, new file `src/research/pruning.ts`_

**A1. Source Dedup & Eviction**

- Add Jaccard-based sub-question dedup in `GapFiller.fillGaps()` before adding to state.
- Implement `state.pruneSources()` — removes sources that have been in `pending` status for >3 gap loops with no extraction results.
- Cap total sources at 2× `maxSources` from budget profile (soft cap, evict lowest-ranked).

**A2. Finding Quality Tiering**

- Split findings into `confirmed` (≥3 sources), `corroborated` (2 sources), `unverified` (1 source).
- In-flight trim: when findings exceed `maxExtractions * 3`, drop lowest-confidence `unverified` findings first.
- `compaction.ts`: rank findings by `evidenceWeight * freshness` before capping, not by insertion order.

**A3. State Size Guard**

- Add `maxStateEntries` to `BudgetProfile` (500 for standard, 2000 for exhaustive).
- When exceeded, evict: (1) sources with no findings, (2) findings with single source + low confidence, (3) oldest gap records.

### Phase B: Error Recovery Hardening

_Estimated: 2–3 days. Touches: `discovery.ts`, `extraction.ts`, `workerAgent.ts`, new file `src/research/retry.ts`_

**B1. Retry with Exponential Backoff**

- Create `withRetry(fn, options)` wrapper: exponential backoff (1s→2s→4s→8s→16s), jitter, max 3 retries.
- Classify errors: `TRANSIENT` (429, 503, ETIMEDOUT, ECONNRESET) vs `PERMANENT` (400, 403, 404, ENOTFOUND).
- Apply to: discovery searches (per-backend), extraction (per-source), LLM calls (per-request).
- Do NOT retry: budget exhaustion, abort signals, permanent errors.

**B2. Circuit Breaker for Backends**

- Track per-backend failure rates in sliding window (last 10 calls).
- If failure rate > 80%, skip backend for 60s (fast-fail with cached degraded status).
- `health.ts` already tracks backend health — wire that into discovery.

**B3. Escalating Recovery**

- `recoverSubQuestion()`: 3-pass escalation — (1) stripped keywords, (2) LLM-rewritten query, (3) single-term fragments.
- If all passes fail, mark sub-question `unresolvable` (not `low_confidence`) to prevent gap-loop re-attempts.

### Phase C: Tree Engine Guardrails

_Estimated: 2 days. Touches: `treeEngine.ts`_

**C1. Topic-Drift Detection**

- Before recursing into `deepResearch(nextQuery, …)`, compute cosine similarity between `nextQuery` embedding and original query embedding.
- If similarity < 0.3, skip recursion and log `"Branch pruned: semantic drift detected"`.
- Embed original query once at `run()` entry, reuse across all levels.

**C2. Multi-Follow-Up Exploration**

- Don't discard `followUpQuestions[1:]`. Process all follow-ups with reduced breadth (`Math.max(1, breadth/3)`).
- Cap total follow-ups per node at 3.

**C3. Failed Query Filtering**

- Filter out `"No findings for: ..."` learnings from aggregation output.
- Track per-branch finding yield — if a branch produces 0 findings after 2 levels, prune it.

**C4. Dynamic Context Budget**

- Split `contextWordLimit` proportionally across branches: `limitPerBranch = contextWordLimit / (breadth^depth)`.
- This prevents shallow branches from consuming budget that deeper branches need.

### Phase D: Gap Loop Optimization

_Estimated: 1–2 days. Touches: `orchestrator.ts`, `gapAnalysis.ts`, `state.ts`_

**D1. Confidence Plateau Detection**

- Track `findingsAddedPerLoop[]` in `BudgetTracker`.
- If last 2 loops each added <5% of total findings, break the gap loop early.
- Log: `"Gap loop plateau detected — findings per loop below threshold"`.

**D2. Priority-Based Loop Budget**

- Only spawn workers for critical gaps (priority ≤ 2).
- Low-priority gaps (3–5) get batched into a single search pass without worker agents.
- This prevents the "burning budget on de-prioritized gaps" anti-pattern.

**D3. Time Budget Progress Check**

- `extendRuntime()` should require a minimum finding yield since last extension.
- If `findingsAdded / additionalMs < threshold`, deny extension.

### Phase E: In-Flight Compaction

_Estimated: 3–4 days. Touches: new file `src/research/compactionInFlight.ts`, `orchestrator.ts`_

**E1. Staged Compaction (inspired by OpenDev ACC)**

- Monitor state size at phase boundaries (after discovery, after extraction, after each gap loop).
- Stage 1 (70% of soft limit): Log warning, no action.
- Stage 2 (85%): Evict sources with no findings and age > 1 gap loop.
- Stage 3 (95%): Compress findings — drop `evidenceExcerpt`, keep `evidenceSummary` + `claim`.
- Stage 4 (99%): LLM-based summarization of oldest findings into a compressed knowledge block.

**E2. Tool Result Optimization**

- Replace raw source content in state with metadata + summary after extraction completes.
- Store full content offloaded to temp file (claim-check pattern from `compaction.ts`).

### Phase F: Citation URL Validation

_Estimated: 1–2 days. Touches: new file `src/research/urlHealth.ts`, `synthesizer.ts`_

**F1. URL Liveness Checking**

- Before including a URL in the final report, validate it: HTTP HEAD request (5s timeout).
- Classify: `LIVE` (2xx/3xx), `DEAD` (4xx/5xx), `UNKNOWN` (timeout/connection error).
- For `DEAD` URLs, check Wayback Machine — if archived, mark `STALE`; if not, mark `HALLUCINATED`.

**F2. Report Impact**

- Strip `HALLUCINATED` URLs from report citations.
- Add `STALE` URLs with `[archived]` annotation.
- Surface URL health stats in `CompactStatistics`.

## 5. Risks & Mitigations

| Risk                                                          | Mitigation                                                                                                |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| In-flight compaction degrades synthesis quality               | Stage 4 (LLM summarization) is opt-in via config. Stages 1–3 are lossless (eviction only of unused data). |
| Topic-drift detection false-positives (prunes valid branches) | Set similarity threshold low (0.3). Log all pruned branches for debugging.                                |
| URL validation adds latency                                   | Batch URL checks with concurrency=10. Timeout per URL at 5s. Total validation under 30s for 100 URLs.     |
| Circuit breaker masks temporary outages                       | 60s cooldown with automatic re-enable. Log every trip.                                                    |
